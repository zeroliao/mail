# 邮箱账号管理系统测试计划

## 1. 文档目标

- 为邮箱账号管理系统建立可执行的测试范围、测试策略和验收标准。
- 先行定义后续 API 自动化测试和联调测试的边界，便于后端工程师补齐接口后直接落地。
- 明确当前阻塞项，避免在缺少真实接口契约时虚构测试实现。

## 2. 当前状态与关键假设

- 当前工作区未发现邮箱账号管理系统代码、OpenAPI 文档、接口定义、数据库模型或现成测试框架。
- 当前仓库实际内容是单文件 Python 自动化脚本，与本测试任务目标不一致。
- 因此本阶段交付以测试计划、测试清单和自动化测试设计为主，不直接提交 API 测试代码实现。
- 后续接口自动化默认优先使用 `Vitest`；若后端已有 `Jest` 约定，则遵循后端现有测试栈。

## 3. 测试目标

- 验证 Gmail / Outlook / Hotmail 账号的绑定、切换、收发邮件主流程可用。
- 验证 OAuth2 授权、Token 刷新、异常恢复和多账号上下文隔离正确。
- 验证邮件列表分页、过滤、排序、状态同步等核心业务行为正确。
- 验证接口错误处理、安全校验和输入验证符合预期。

## 4. 测试范围

### 4.1 In Scope

- 账号绑定/解绑
- OAuth2 授权回调与 state 校验
- Token 刷新
- 邮件列表获取（分页、过滤、排序）
- 发送邮件
- 多账号切换
- API 异常处理
- 输入校验与常见安全防护

### 4.2 Out of Scope

- 邮件正文渲染兼容性细节
- 大规模性能压测
- 第三方邮箱服务商 SLA 验证
- 未进入本期范围的管理后台或统计报表功能

## 5. 测试策略

### 5.1 单元测试

目标：快速验证纯逻辑与边界条件，隔离外部依赖。

覆盖建议：

- OAuth2 URL 构造、state 生成与校验
- Token 过期判断与刷新策略
- 邮件列表查询参数解析
- 分页参数校验
- 过滤条件规范化
- 发信请求 DTO 校验
- 邮箱地址、主题、附件元数据校验
- 错误码映射与统一异常包装

策略：

- 外部依赖全部 mock，包括 Gmail API、Microsoft Graph API、数据库、缓存、消息队列。
- 重点覆盖边界值、空值、非法值、重复提交、状态转换。
- 对 state、token、accountId 等敏感字段增加异常分支断言。

### 5.2 集成测试

目标：验证模块间协作、数据库读写、OAuth2/token/mail provider 适配层行为。

覆盖建议：

- 账号绑定后账号记录落库
- 解绑后本地账号状态更新、token 失效或软删除
- 刷新 token 成功后新 token 持久化
- 刷新 token 失败后错误状态和重试策略
- 邮件列表接口正确组合数据库缓存与第三方邮件服务响应
- 多账号切换时上下文、token、数据隔离正确

策略：

- 优先使用测试数据库和 provider mock server。
- 若已有 OpenAPI mock / sandbox account，优先接入官方 sandbox。
- 对 Gmail / Outlook / Hotmail 分别保留一组 provider 适配测试。

### 5.3 E2E 测试

目标：验证真实用户路径和跨系统主链路。

核心场景：

- 用户发起 Gmail 绑定并完成 OAuth2 授权
- 用户发起 Outlook / Hotmail 绑定并完成 OAuth2 授权
- 用户切换多个账号查看各自邮件列表
- 用户选择指定账号发送邮件并收到成功反馈
- token 过期后自动刷新并继续完成请求
- provider 返回授权失效时前端/接口提示重新授权

策略：

- 使用真实测试账号，严格隔离测试邮箱与正式邮箱。
- 对关键链路保留最少但稳定的冒烟用例，避免 E2E 过重。
- 对 OAuth2、外链授权、回跳 URL、state 参数做全流程校验。

## 6. 核心 API 测试设计

说明：以下为后续 Jest/Vitest 自动化实现的最小核心集合，待后端提供真实接口路径、请求/响应 schema、鉴权方式后落地。

### 6.1 账号绑定接口

建议覆盖：

- 正常绑定 Gmail 账号成功
- 正常绑定 Outlook 账号成功
- 正常绑定 Hotmail 账号成功
- 缺少必填参数时返回 4xx
- 无效授权 code 返回绑定失败
- 重复绑定同一第三方账号时返回冲突或幂等成功
- OAuth state 不匹配时拒绝绑定
- provider 返回 token 过期/撤销时正确透出错误

关键断言：

- 返回 accountId、provider、status、绑定时间
- token 不明文泄露到响应体
- 数据库存储 provider 用户唯一标识
- 重复绑定不产生脏数据

### 6.2 账号解绑接口

建议覆盖：

- 已绑定账号正常解绑成功
- 解绑不存在账号返回 404
- 解绑他人账号返回 403/404
- 重复解绑已解绑账号时行为符合幂等设计
- 解绑后不可继续获取该账号邮件列表

关键断言：

- 本地状态变更为 unbound / inactive
- token 被删除、失效或不可再用
- 审计日志或操作记录写入成功

### 6.3 邮件列表获取接口

建议覆盖：

- 默认分页查询成功
- 指定 `page` / `pageSize` 成功
- `page=0`、负数、超大 `pageSize` 返回参数错误
- 按未读状态过滤
- 按发件人过滤
- 按日期范围过滤
- provider/accountId 不匹配时拒绝访问
- token 过期触发刷新后查询成功
- provider 超时返回可识别错误

关键断言：

- 返回分页元信息：`page`、`pageSize`、`total`
- 返回邮件字段完整：`id`、`subject`、`from`、`receivedAt`、`read`
- 过滤条件只影响当前账号，不串数据

### 6.4 发送邮件接口

建议覆盖：

- 发送纯文本邮件成功
- 发送 HTML 邮件成功
- 缺少 `to` / `subject` / `body` 返回参数错误
- 非法邮箱地址返回参数错误
- 未绑定账号发信被拒绝
- token 过期后刷新成功并继续发信
- provider 限流/超时/服务错误时正确返回

关键断言：

- 返回 messageId 或 providerMessageId
- 不重复发送
- 发信账号与当前选中账号一致
- HTML 内容经过必要安全过滤策略

### 6.5 Token 刷新接口

建议覆盖：

- 有效 refresh token 刷新成功
- 缺少 refresh token 返回 4xx
- refresh token 失效返回重新授权错误
- provider 网络超时返回可重试错误
- 并发刷新同一账号时避免重复覆盖

关键断言：

- 新 access token 生效并持久化
- 旧 token 不再继续使用
- 刷新失败时不污染已有可用数据

## 7. 验收测试清单

### 7.1 Gmail / Outlook / Hotmail 收发邮件

- Gmail 绑定后可收邮件、发邮件、刷新列表
- Outlook 绑定后可收邮件、发邮件、刷新列表
- Hotmail 绑定后可收邮件、发邮件、刷新列表
- 三类账号均可读取未读/已读状态
- 三类账号均可正确显示发件人、主题、时间

### 7.2 多账号切换

- 同一用户绑定多个账号后可切换查看各自邮件
- 切换账号后列表数据、发信账号、筛选条件上下文正确
- 切换过程中不会串 token、串邮箱数据、串发送身份

### 7.3 OAuth2 授权流程

- 发起授权跳转参数正确
- 回调 code/state 处理正确
- 用户取消授权时提示明确
- provider 返回授权失败时提示明确
- token 过期后自动刷新；刷新失败时引导重新授权

### 7.4 API 错误处理

- 无效 token
- 过期 token
- 无效 refresh token
- provider 网络超时
- provider 429 限流
- provider 5xx 服务异常
- 非法参数
- 未授权访问他人账号

## 8. 安全测试项

### 8.1 输入验证

- `email`、`subject`、`body`、`page`、`pageSize`、`filter` 必填/格式/长度校验
- 过长主题、异常字符、空白字符、超大分页参数
- 附件文件名、MIME type、大小限制

### 8.2 SQL 注入防护

- 查询参数、筛选参数、accountId、messageId 注入字符测试
- 断言接口不会报 SQL 语法错误，不会返回越权数据

### 8.3 XSS 防护

- 邮件主题、HTML body、搜索关键字注入脚本片段
- 断言返回内容经过转义/净化，前端展示不执行脚本

### 8.4 OAuth state 参数验证

- state 缺失
- state 不匹配
- state 重放
- state 过期

断言：

- 一律拒绝授权完成
- 记录安全日志
- 不生成绑定关系

## 9. 测试数据与环境建议

- 每个 provider 准备至少 2 个独立测试账号：一个主账号，一个辅助收件账号。
- 提供一套可反复回收的测试邮件样本：纯文本、HTML、长主题、特殊字符、附件邮件。
- 区分本地 mock 环境、测试环境、准生产环境。
- 测试环境需要可观察日志、错误码、请求链路 ID。
