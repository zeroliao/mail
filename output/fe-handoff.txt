@前端工程师 Task#16『Token 直连导入』接口契约（可直接开工，与现有 IMAP 直连同页 AuthBindingPage 风格对齐）：

【接口 1 — 单个】POST /api/v1/accounts/bind-oauth（需 Bearer）
请求体: { email, clientId, refreshToken, displayName?, scope?(string[]), tenant? }
成功 200: { status:"success", message:"已绑定 xxx", account:{ id, email, provider:"MICROSOFT", status:"ACTIVE", providerLabel:"Outlook / Hotmail" } }
失败: 400=参数缺失(zod)，401=未登录，502=连通性校验失败（message 为中文/微软原始 error，details 含微软错误体如 invalid_grant/invalid_scope/AADSTS70000）。前端直接展示 message 即可。

【接口 2 — 批量】POST /api/v1/accounts/bind-oauth/batch（需 Bearer，≤100 条）
请求体: 数组 [{ email, clientId, refreshToken, displayName?, scope?, tenant? }, ...]
成功 200: { total, success, failed, results:[{ email, status:"success"|"failed", message, accountId? }, ...] }
逐条互不影响——按 results 逐行渲染成功/失败（失败显示 message）。

【接入位置（沿用现有模式）】
1) src/services/mailApi.ts：仿照已有 bindCredentials，新增
   bindOAuth(email, clientId, refreshToken, opts?) -> POST /accounts/bind-oauth
   bindOAuthBatch(items[]) -> POST /accounts/bind-oauth/batch
   （apiClient baseURL 已是 /api/v1，路径写相对即可；token 由 setAuthToken 注入。）
2) src/store/useMailAppStore：仿 bindCredentials 加 bindOAuth/bindOAuthBatch action，成功后触发账户列表刷新（与现有 refresh 一致）。
3) src/pages/AuthBindingPage.tsx：在「账号密码直连」Card 下方新增一张 Card「Token 直连导入（Outlook / Hotmail）」：
   - 单个表单：邮箱 / Client ID / Refresh Token（Input.Password）+ 可选 显示名 / scope；按钮 disabled={!isAuthenticated} loading={isBinding}。
   - 批量：一个 Textarea，约定每行 `email,clientId,refreshToken`（前端 split 成数组调 batch），结果用 List 逐条展示成功/失败 Tag+message。
   - 文案提示：适用于「邮箱+密码+client_id+refresh_token」格式；scope 默认走 Graph（Mail.ReadWrite/Mail.Send/offline_access），无需填。

注意：provider 固定回 "MICROSOFT"（providerLabel "Outlook / Hotmail"），落库即 ACTIVE，收发走 Graph，token 过期后端用 per-account clientId 自动刷新——前端无需关心刷新。无需等 owner 真实账号即可联调（用任意值会返回 502+错误体，正好可验证错误展示链路）。有契约疑问本频道 @我。
